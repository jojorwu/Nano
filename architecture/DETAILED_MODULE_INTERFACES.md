# Технические Контракты Модулей Nano

Этот документ определяет программные интерфейсы (Traits) и протоколы взаимодействия между ядром Nano Core и внешними модулями.

## 1. Трейт `NanoModule` (Rust)

Каждый модуль должен реализовывать базовый набор методов для интеграции в жизненный цикл симуляции.

```rust
pub trait NanoModule {
    /// Инициализация модуля с учетом конфигурации SoA
    fn init(&mut self, config: &ModuleConfig);

    /// Фаза DAY: Обработка входных сигналов и генерация спайков
    /// Вызывается на каждом тике.
    fn on_tick(&mut self, core_state: &mut NeuronsSoA);

    /// Фаза NIGHT: Структурная адаптация и обучение
    /// Вызывается периодически.
    fn on_night_phase(&mut self, synapse_state: &mut SynapsesSoA);

    /// Обработка команд управления "на лету"
    fn handle_command(&mut self, cmd: Command) -> Response;
}
```

## 2. Протокол "Spike Injection"

Модули кодирования (Text/Vision) взаимодействуют с ядром через инъекцию потенциалов.

- **Direct Potential Injection:** Модуль увеличивает значение `potential[i]` целевого нейрона.
- **Current Injection:** Модуль добавляет "ток" в синаптическую очередь, имитируя внешние сенсорные нейроны.

## 3. Регистрация данных в SoA

Для сохранения "Zero-Cost" эффективности, модули могут регистрировать свои собственные массивы данных, которые будут обрабатываться вычислительным бэкендом (Compute Backend) параллельно с основным ядром.

```rust
// Пример регистрации дополнительного параметра нейрона для модуля Titan
core.register_soa_column("momentum", DataType::I32);
```

## 4. Командный интерфейс (Runtime IPC)

Модули должны поддерживать асинхронные команды. Формат команд базируется на JSON-RPC 2.0 для легкости интеграции с Python и внешними CLI.

### Пример сообщения:
```json
{
  "jsonrpc": "2.0",
  "method": "module.titan.set_momentum",
  "params": {"value": 950},
  "id": 1
}
```

## 5. Требования к производительности

1.  **No Allocations in Loop:** Методы `on_tick` не должны выделять память (никаких `Vec::new`, `Box` и т.д.).
2.  **SIMD Friendliness:** Данные должны быть выровнены по границе 64 байт для эффективного использования AVX-512.
3.  **Atomic Swaps:** Все изменения топологии в фазе Night должны фиксироваться через атомарные операции для исключения Race Conditions с фазой Day.
