# Архитектура Nano Spiking Engine: Модульное проектирование

В этом документе представлена концепция архитектуры Nano — высокопроизводительной, модульной и ресурсосберегающей спайковой нейросети.

## 1. Концептуальная схема (ASCII)

```text

           |                                             |
           v                                             v

           |                                             ^
           |  (Baked .state)                             | (SoA Data Flow)
```

## 2. Основные компоненты

### 2.1. Nano Core (Ядро)
Ядро системы написано на Rust и отвечает за:
- **Базовую физику:** Реализация LIF (Leaky Integrate-and-Fire) нейронов в целых числах.
- **SoA Layout:** Хранение данных (потенциалы, веса, синапсы) в плоских массивах для оптимизации кэша.
- **Модульную шину:** Интерфейсы для подключения дополнительных функциональных блоков.

### 2.2. Модульная система (Zero-Cost Modularity)
Модули подключаются через Rust `features` и TOML-конфигурацию:
- **Отключение на этапе компиляции:** Если модуль (например, Vision) не нужен, его код не включается в бинарный файл.
- **Отсутствие оверхеда:** Отключенные модули не резервируют память и не замещают циклы симуляции.

### 2.3. Day/Night Cycle (Двухфазная работа)
- **Day (Inference):** Быстрая фаза обработки сигналов (спайков). Максимальный параллелизм на GPU.
- **Night (Evolution):** Фаза перестройки. CPU выполняет прунинг, проращивание аксонов и обновление весов по правилам пластичности.

## 4. Технологические преимущества

1. **Целочисленная точность (i32):** Детерминизм вычислений позволяет переносить состояние модели между любыми устройствами без потери точности.
2. **Адаптивность (Test-Time Training):** Интеграция механизмов, подобных Titans и DeepSeek MLA, позволяет Nano эффективно работать со сверхдлинными последовательностями.
3. **Ресурсная эффективность:** Nano — это "конструктор", где пользователь платит вычислительными ресурсами только за то, что он явно включил.

## 5. План реализации структуры

1. **`genesis-core`**: Определение трейтов и базовых структур SoA.
2. **`genesis-compute`**: Изоляция математики от логики (Backend trait).
3. **`modules/`**: Папка для независимых плагинов (Vision, Text, Audio).
4. **`genesis-node`**: Оркестратор жизненного цикла.
