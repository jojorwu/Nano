# Техническая Спецификация Архитектуры Nano v2.1

Этот документ является исчерпывающим руководством по архитектуре Nano — высокопроизводительного, модульного движка для симуляции спайковых нейронных сетей (SNN). Версия 2.1 включает улучшения в области динамической маршрутизации, энергоэффективности и предиктивного обучения.

## 1. Концептуальная схема и Иерархия (ASCII)

Nano спроектирован для бесшовного масштабирования: от одиночных Edge-устройств до глобальных кластеров.

```text
УРОВЕНЬ 1: Nano Cluster (Глобальный оркестратор)
|   (RDMA Spike Bus, Балансировка нагрузки, Синхронизация шардов)
|
|-- УРОВЕНЬ 2: Nano Node (Локальный узел - Rust)
|   |   (Day/Night Цикл, Управление IPC, Владение SoA-памятью)
|   |
|   +-- УРОВЕНЬ 3: Compute Backend (Вычислительные ядра)
|       |   (CUDA/HIP Kernels для GPU, NPU Driver, AVX-512 для CPU)
|       |
|       +-- УРОВЕНЬ 4: Feature Modules (Zero-Cost Модули)
|           |   (Text, Vision, Audio, Titan Memory, New Custom Modules)
```

## 2. "Zero-Cost" Модульность и Ресурсная Эффективность

Философия Nano строится на принципе "плати только за то, что используешь":
- **Compile-time Resolution:** Неиспользуемые модули исключаются на этапе компиляции через Rust `features`. Это гарантирует отсутствие мертвого кода в бинарном файле.
- **Runtime Gatekeeping:** Пользователь может мгновенно активировать или деактивировать логику включенных модулей через команды `mod <name> toggle`.
- **Изоляция ресурсов:** Отключенные модули не резервируют VRAM и не потребляют такты GPU.

## 3. Продвинутая Нейронная Динамика (Новое в v2.1)

### 3.1. Динамическая Маршрутизация Спайков (Dynamic Routing)
Вместо жестко заданных адресов нейронов, Nano внедряет **Spike-driven Address Event Representation (AER)**. Это позволяет:
- Снизить объем передаваемых данных в 2-3 раза.
- Динамически перенаправлять сигналы в обход перегруженных узлов кластера.

### 3.2. Предиктивная фаза Night (Predictive Evolution)
Теперь фаза Night не просто удаляет старые связи (прунинг), но и анализирует паттерны активности для **превентивного роста аксонов**. Это позволяет сети быстрее адаптироваться к новым типам входных данных.

### 3.3. Энергозависимое Планирование (Energy-Aware Scheduling)
Для Edge-устройств Nano поддерживает режим "Low Power", где частота тиков и глубина пластичности автоматически снижаются при нехватке энергии.

## 4. Гибридный технологический стек (Language Synergy)

Мы используем оптимальный язык для каждой задачи:

| Слой системы | Языки | Роль и Технологии |
| :--- | :--- | :--- |
| **Оркестрация** | **Rust** | `nano-node`. Безопасная многопоточность (`tokio`), IPC. |
| **Вычисления (Day)** | **CUDA / HIP** | "Мышцы". Проход по графу спайков, вычисление токов. |
| **Эволюция (Night)** | **C++ / Rust** | "Логика". Прунинг, рост аксонов. Интеграция с графовыми библиотеками. |
| **Интерфейс (API)** | **Python** | "Лицо". `nano-python` (`PyO3`). Настройка и визуализация. |

## 6. Решение критических узких мест

1.  **Масштабируемость памяти:** Distributed Sharding через асинхронные прокси-связи (Ghost Axons v2).
2.  **Латентность передачи:** Spike Compression с использованием битовых масок.
3.  **Thread Contention:** Lock-free Topology Updates через Double Buffering SoA.
4.  **Точность i32:** Adaptive Scaling — автоматическая регулировка масштаба вычислений.

## 7. Расширяемость и AI v2

Любой разработчик может добавить новый функционал, реализуя трейт `NanoModule`. Nano поддерживает экспорт обученных моделей в изолированные папки (`Standalone AI`), которые полностью готовы к работе на целевом оборудовании.
