# Архитектура Nano Spiking Engine

Этот документ описывает внутреннюю структуру и принципы работы модульной спайковой нейронной сети Nano с памятью типа Titan.

## 1. Основные принципы

Система построена на трех китах:

1.  **Integer Physics (Целочисленная физика):** Все вычисления (потенциалы, веса, затухание) выполняются с использованием фиксированной запятой (`i32`). Базовый масштаб `SCALE = 1000` (соответствует 1.0). Это обеспечивает детерминизм и высокую скорость на любом железе.
2.  **Structure of Arrays (SoA):** Данные нейронов и синапсов хранятся в плоских параллельных векторах, а не в объектах. Это оптимизирует использование кэша процессора и упрощает будущую интеграцию с GPU (SIMD/CUDA).
3.  **Day/Night Cycle:** Разделение работы на быструю фазу инференса (Day) и медленную фазу обучения/перестройки (Night).

## 2. Структура Workspace (Crates)

Проект разделен на несколько специализированных библиотек и приложений:

-   `genesis-core`: Ядро. Содержит типы данных (SoA), базовую логику спайков, модули Titan Memory, Vision и Text, а также законы пластичности.
-   `genesis-compute`: Вычислительный бэкенд. Определяет трейт `ComputeBackend` и его реализацию для CPU. Здесь живет математика симуляции.
-   `genesis-baker`: Компилятор моделей. Читает TOML-чертежи (blueprints) и "запекает" их в бинарные файлы состояния (`.state`).
-   `genesis-node`: Оркестратор. Управляет жизненным циклом модели, переключает фазы Day/Night и взаимодействует с бэкендом.
-   `axicor-cli`: Командный интерфейс для пользователя. Позволяет собирать модели и запускать их с текстом или изображениями.

## 3. Модульная система

Функционал нейросети собирается из независимых модулей через систему `features` в Rust и конфигурацию в TOML:

-   **Titan Memory:** Адаптивная память, которая учится прямо во время работы (test-time) через упрощенный градиентный спуск с моментом.
-   **Text Processor:** Токенизатор и кодировщик, превращающий слова в паттерны импульсов.
-   **Vision Module:** Модуль интенсивного кодирования (Rate Encoding) для обработки изображений.

## 4. Формат данных

-   **Blueprints (.toml):** Описание архитектуры (кол-во нейронов, синапсов) и список включенных модулей.
-   **Model State (.state):** Бинарный файл (сериализация `bincode`), содержащий все веса, потенциалы, топологию синапсов и накопленный словарь. Автоматически сохраняется после каждого запуска.

## 5. Логика работы (Tick Loop)

Один тик симуляции в `genesis-node` выглядит так:

1.  **Day Phase (Inference):**
    -   Сбор внешних входов.
    -   Распространение импульсов через синапсы.
    -   Чтение сигналов из Titan Memory.
    -   Обновление потенциалов нейронов и генерация новых спайков.
2.  **Night Phase (Evolution):**
    -   Срабатывает каждые N тиков.
    -   Обновление весов по закону пластичности (GSOP).
    -   Обучение Titan Memory на основе "сюрприза" (ошибки предсказания).
    -   Структурная эволюция: удаление слабых связей (pruning) и создание новых между активными нейронами (growth).
