# Руководство по разработке новых модулей для Nano

Это руководство предназначено для разработчиков, желающих расширить функционал Nano путем создания собственных модулей (например, Audio, RobotControl, Smell и т.д.).

## 1. Структура модуля

Все новые модули должны располагаться в `genesis-core/src/` (или в отдельной папке `modules/` в будущем) и подключаться через систему `features`.

### Пример: Создание модуля "Smell" (Обоняние)

#### Шаг 1: Регистрация в Cargo.toml
Добавьте новую фичу в `genesis-core/Cargo.toml`:
```toml
[features]
smell = []
```

#### Шаг 2: Создание файла src/smell.rs
Реализуйте базовую логику модуля:

```rust

pub struct SmellModule {
    pub sensitivity: i32,
    pub active: bool,
}

impl SmellModule {
    pub fn new() -> Self {
        Self { sensitivity: 100, active: true }
    }

    /// Вызывается каждый тик в фазе Day
    pub fn process_odors(&mut self, input_data: &[u8]) {
        if !self.active { return; }
        // Превращение химических сигналов в спайки...
    }

    /// Вызывается в фазе Night для дообучения
    pub fn evolve(&mut self) {
        // Уточнение рецепторов...
    }
}
```

#### Шаг 3: Интеграция в Nano Core
В `genesis-core/src/lib.rs`:
```rust

pub mod smell;

pub struct BakedModel {
    // ...
    #[cfg(feature = "smell")]
    pub smell_module: Option<smell::SmellModule>,
}
```

## 2. Основные правила (Nano Module Laws)

Чтобы ваш модуль работал эффективно и не замедлял систему, следуйте этим правилам:

1.  **Integer Only:** Используйте только `i32` или `i16` для внутренних расчетов. Никаких `f32/f64`.
2.  **SoA First:** Если модулю нужно хранить состояние для тысяч элементов, используйте структуру массивов (SoA).
3.  **Command Support:** Реализуйте поддержку команд для живой настройки через `handle_command`.
4.  **Zero Cost:** Если фича отключена, код модуля не должен влиять на производительность ядра.

## 3. Идеи для новых модулей
- **Audio Processor:** Превращение звуковых волн в темпоральные паттерны спайков.
- **Motor Controller:** Интерфейс для управления сервоприводами роботов на основе выходных импульсов.
- **Hierarchical Memory:** Дополнительный уровень памяти для долгосрочного хранения абстрактных понятий.
- **Social Interaction:** Модуль для моделирования поведения в группе агентов.
